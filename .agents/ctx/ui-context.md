# UI Context

The Metis web app (`web/`). UI only: it talks to the server API and nothing else (no LLM, DB, Exa or MCP calls). Read with `project-overview.md`, `architecture.md` and `code-standards.md`.

Reference designs (source of truth for look and behavior):

- `design/samples/metis-workspace-shadcn.html`: **idea workspace** (current): bottom-anchored chat, answer options, output panel, account menu, settings sheet
- `design/samples/metis-chat-shadcn.html`: earlier chat-only version (superseded by the workspace for the conversation layout)
- `design/samples/metis-auth-shadcn.html`: sign-in page

Open them in a browser before building a screen. Match them; do not restyle.

| Forms         | `react-hook-form` + `zod` (`@hookform/resolvers/zod`)                                   | One Zod schema per form, shared with server actions if any              |

## Routes

| Route             | Access    | Screen                                                                                                                                                          |
| ----------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/sign-in`        | public    | Split: pitch left, form right (form first on mobile)                                                                                                            |
| `/`               | signed in | Empty chat: "What are you building?", suggestions, composer                                                                                                     |
| `/ideas/[ideaId]` | signed in | Idea workspace: conversation + output panel                                                                                                                     |
| `?panel=<pane>`   | signed in | Opens the output panel on `/ideas/[ideaId]`. Panes: `score`, `research`, `suggestions`, `spec`, `plan`. Spec and plan live in the panel, not on separate routes |
| `?settings=<tab>` | signed in | Opens the settings sheet on any app route. Tabs: `account`, `keys`, `integrations`, `prefs`                                                                     |

Auth: server-owned Google sign-in (`plans/server-auth-google.md`). "Continue with Google" is a plain link to `/v1/auth/google/login?redirect_to=<path>`. The web holds no auth SDK and no tokens; the session is an `HttpOnly` cookie. The `(app)` layout calls `GET /v1/me` on the server; `401` redirects to `/sign-in`. Mutations send `X-Metis-Client: web`. Render provider buttons from `GET /v1/auth/providers`; email shows as "Soon".

> `architecture.md` still says Auth.js. If the auth plan is accepted, update `architecture.md` in the same change.

## Design Language

Sharp, compact, quiet. Linear-style density on shadcn neutral tokens.

1. **Square everything.** `--radius: 0`. No `rounded-*` anywhere, including avatars, pills, inputs, tooltips and the send button. Only spinners may be round.
2. **Lines, not shadows.** Structure comes from 1px `border` lines. Shadows only on floating layers (popover, sheet).
3. **Frame and grid.** Content sits in a bordered safe area; lines run edge to edge with `+` ticks where they cross (see Layout).
4. **Neutral first.** Color only for meaning: score bands, status dots, destructive.
5. **Compact.** 13px base, 28–30px controls, 44px header.
6. **Agent text has no bubble.** User messages are filled blocks on the right; agent replies are plain text on the left.
7. **Chat is for conversation only.** Reports, scores, suggestions, specs and exports never render inside the chat. The chat shows a one-line `OutputCard`; the content lives in the `OutputPanel`.
8. **Pick before you type.** When Metis asks something, the input area shows answer options with one marked "Best fit". Typing is the fallback ("Something else"). The free-text box shows only for a new idea, a typed answer, or open follow-ups.
9. **Bottom-anchored.** Like a messenger: messages stack upward from the input area; empty space sits at the top.

## Layout: Frame and Grid

`components/frame/` renders a fixed background layer (`pointer-events-none`, `z-0`) under the app:

| Piece         | Spec                                                                                                                                                                                                                                                                                                                         |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Side rails    | Areas outside `--frame`, filled with concentric 1px circles (`stroke: foreground` at 9% opacity, r 60→1800 step 16, centre 140px past the outer edge; left at 38% height, right mirrored at 72%). One SVG per side, generated once.                                                                                          |
| Safe area     | `--frame` wide, `bg-background`, `border-x`                                                                                                                                                                                                                                                                                  |
| Column guides | 1px vertical lines at the chat column edges, centred in the chat pane, full height through header and footer. The chat column is 760px, or fills the chat pane when the pane is 920px or narrower (always the case with the panel open on laptop widths)                                                                     |
| Header line   | `border-b` full viewport width at `--header-h`                                                                                                                                                                                                                                                                               |
| Footer line   | `border-t` full viewport width at `--footer-h` from the bottom                                                                                                                                                                                                                                                               |
| Input band    | 1px line at the top edge of the active dock mode (composer, options or working bar), from the history panel's right edge (or the viewport's left edge when it is closed) to the output panel's left edge (or the right viewport edge when it is closed); footer line closes it |
| History edge  | When the history panel is open: a 1px vertical line at its right edge, full height; the input band starts there instead of the viewport's left edge                                                                                                                                                                          |
| Panel edge    | When the output panel is open: a 1px vertical line at its left edge, full height through header and footer                                                                                                                                                                                                                   |
| Cross ticks   | 9×9 `+` (muted-foreground, 60%) at every crossing of a vertical line (frame, column guides, panel edge) with the header line, footer line and input band. Positions depend on the panel and dock height, so compute them from element rects (`ResizeObserver` on the dock and chat pane, re-run during the panel transition) |
| Measuring     | `useFrameLines` reads elements marked `data-frame="safe \| column \| header \| footer \| band \| history \| output"` (`history` and `output` count while the panel has width, so lines and ticks follow it as it slides shut, and only from 820px up) (`column` is the zero-height probe at the top of the chat pane, a `chat-col`: as wide as `--col`, or the whole pane when the pane is 920px or narrower, found by a container query) and re-measures on resize, on a part mounting or unmounting, and during width transitions. `GridGuides` places guides, band and ticks from it; their `left`/`top` are the only inline styles in the frame. The band line sits in the pixel row above the composer, which paints over its own first row. A guide on a frame edge is drawn once |

Workspace layout inside the frame: `[history panel | chat pane | output panel]`. The history panel is 264px, opens from the left and pushes the chat pane; under 1200px opening one side panel closes the other. Under 820px it is an overlay from the left (max 320px, `--overlay-w`) with a scrim that closes it. While an overlay is open the chat pane is `inert`.

Output panel: The panel is `clamp(360px, 36vw, 500px)` wide, pushes the chat pane narrower (width transition 250ms), and stays open while you keep chatting. Under 820px it becomes a full-screen overlay from the right with its own close button (it covers the page, so it has no scrim).

Panel state (`useWorkspacePanels`, in `lib/workspace/`): history open state is local; the output panel is `?panel=score|research|suggestions|spec|plan`, written with `history.replaceState` and read back through `useSearchParams` behind its own `Suspense`, so pages still prerender. An unknown value opens nothing. Both panels are `<aside>` landmarks, `inert` while closed, and carry `data-frame` and `data-open`. A pane without content has a disabled tab, and `?panel=` still opens the shell on it (placeholder body). Which panes have content, and whether an output is unseen, come from `OutputAvailabilityContext` (empty until the output panes register theirs). Keys: `/` opens history (not while typing); Esc closes the panel opened last (not while typing, and not while a dialog or menu is open) and returns focus to its toggle; under 820px opening a panel focuses its close button.

Header and footer are transparent so rails show through. Under 820px: hide column guides, panel edge and their ticks. Under 700px: hide rails and frame ticks, frame is full width without side borders. `html, body { overflow-x: clip }` so the full-width lines never cause horizontal scroll.

## Live Run Events → UI

`useRunEvents(runId)` opens `GET /v1/runs/{id}/events`, parses each event with a Zod schema and feeds a reducer that builds the agent message. Unknown events are ignored.

| Event                             | UI effect                                                                                                                            |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `run.status`                      | Composer busy state; stage label                                                                                                     |
| `step.started` / `step.finished`  | Add step row (spinner) / mark it done                                                                                                |
| `step.progress`                   | Shimmer text, optional `current/total`                                                                                               |
| `tool.called`                     | Step row detail (summary only)                                                                                                       |
| `token`                           | Append streamed text with caret                                                                                                      |
| `research.item`                   | Add to the Research pane; count on its tab                                                                                           |
| `score.param` / `score.completed` | Fill a rubric row / post a score `OutputCard`, open the panel on Score the first time, show the delta on later versions              |
| `interrupt` (question)             | Stop streaming; post the question line; Dock → `ChoicePicker` when the payload has options, else the `Composer`. A pick sends `{option_ids}`; "Something else" opens the composer for that question only (back button returns) |
| `run.finished`                    | Clear busy state; show message actions                                                                                               |
| `run.failed`                      | Inline error row with `detail`; Retry when `retryable`                                                                               |

Reconnect with `Last-Event-ID`; the server pings every 15 s.

Outputs open the panel once, when first produced (score, suggestions, spec). After that, new versions update the pane and light the panel button's dot; they never steal focus while you are answering.

> **Question options (SHIP-294, built).** The server sends the pause as an `interrupt` event: `{type: "question", question, multi, options: [{id, label, detail?, recommended}], allow_free_text, index, total}` (a plain `{type, question}` still works: free text only). The answer is `POST /v1/runs/{id}/resume` with a string, or `{option_ids, text?}` (`{option_ids: [...]}` for a pick, `{option_ids: [], text}` for typed text when options were offered); the server saves the picked labels (several joined with `; `) as the answer. A payload the page cannot read becomes a `notice` ("Metis asked something this page could not read") and the run waits; Stop ends it.

## States

- **Loading:** Shimmer for agent work, skeleton lines (square) for lists. No full-page spinners.
- **Empty:** centered title + one line + suggestions.
- **Errors:** API errors are problem+json; show `title` / `detail` inline near the action, toast only for background failures. Field errors from `errors[]` map to form fields.
- **Disabled:** 35–50% opacity, `cursor-not-allowed`.

## Accessibility

- Every icon-only button: `aria-label` and tooltip.
- Visible focus: 2px `ring` outline, offset 2px; inputs show a 3px ring at 20–25% opacity.
- Thread is `aria-live="polite"`; menus support arrow keys and Esc; sheet traps focus and returns it to the trigger.
- Respect `prefers-reduced-motion`: no shimmer, caret blink, bar or slide animations.
- Contrast: body text uses `foreground`, never `muted-foreground` below 12px on `muted` backgrounds.

## Rules

- Tailwind + shadcn only. No inline styles except CSS variables, no CSS modules, no hex.
- No `rounded-*` classes. If a shadcn component adds one, override via the `--radius` token, not by editing `components/ui/`.
- Validate every form with Zod and every SSE payload with Zod before use.
- API types come only from the generated client; regenerate on server schema change.
- Light and dark must both match the samples before a UI PRD is done.
